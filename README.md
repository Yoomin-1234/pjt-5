# 📈 AI 기반 토스증권 커뮤니티 댓글 증강 및 분석 시스템 (05-pjt)

## 📌 프로젝트 소개

본 프로젝트는 Django 기반 웹 애플리케이션으로, 사용자로부터 주식 회사명을 입력받아 **Selenium**을 활용해 토스증권 커뮤니티의 게시글 데이터를 실시간으로 수집하고, 이를 프로젝트 내 댓글 데이터로 활용합니다.

수집한 데이터는 **정규 표현식 기반 전처리**와 **GMS LLM API**를 통해 부적절한 텍스트를 필터링하고, 기존 의미를 유지하면서 자연스럽게 확장합니다. 또한 AI 기반 댓글 요약 기능을 제공하며, 원본·정제·증강 데이터를 데이터베이스에 저장하고 웹 화면에 통합 출력하는 파이프라인 시스템입니다.

---

## 🛠️ 기술 스택 (Tech Stack)

- **Language**: Python 3.11
- **Framework**: Django 5.2
- **Web Crawling**: Selenium WebDriver, webdriver-manager
- **AI / LLM**: GMS LLM API (`gpt-5-nano`)
- **Styling**: Bootstrap 5.3.3
- **Database**: SQLite3
- **Data Processing**: Python `re` (정규 표현식)

## 👥 팀원 역할 분담

### **소준호 — Django 및 크롤링 담당**

- **F601 (입력 및 검증)**: 회사명 입력 폼 구현 및 빈 값 입력 시 데이터 수집 차단, 입력값 터미널 출력 검증
- **F602 (DB 스키마 구성)**: 6가지 필수 데이터 항목(`실제종목명`, `원본 댓글 목록`, `정제 댓글 목록`, `증강 댓글 목록`, `IQR 임계값 정보`, `생성 일시`)을 저장하는 Django 모델 설계 및 마이그레이션
- **F603 (회사 검색 및 선택)**: Selenium을 활용해 토스증권 검색창 진입, 키워드 입력 및 검색 결과 최상단 회사 자동 선택
- **F604 (커뮤니티 댓글 수집)**: 선택된 종목의 커뮤니티 탭에 접근하여 실시간 댓글 20개 수집
- **F611 (예외 상황 처리)**: 검색 결과가 없거나 댓글이 존재하지 않을 때 사용자에게 상태 안내 메시지 출력

**1. 토스증권 동적 크롤링 및 최상단 종목 자동 선택 (F603, F604)**

사용자가 입력한 회사명을 바탕으로 토스증권 검색 모달을 제어하고, 검색된 최상단 종목으로 이동해 커뮤니티 탭에서 댓글 20개를 안정적으로 수집합니다.

**2. 예외 상황 처리 및 사용자 안내 (F611)**

검색 결과가 존재하지 않거나 수집된 댓글이 없을 경우, Django의 `messages` 프레임워크를 활용해 사용자에게 직관적인 경고 메시지를 띄우고 메인 화면으로 안전하게 리다이렉트합니다.

### **김유민 — 데이터 전처리 및 AI 담당**

- **F605 (댓글 정제)**: 정규 표현식을 활용한 공백 및 특수문자 처리, 불필요한 반복 패턴(`ㅋㅋㅋ`, `ㅎㅎㅎ` 등) 제거, 댓글 길이 필터링(5~76자), GMS LLM API를 활용한 부적절한 댓글(욕설, 혐오, 비방, 선정성 등) 판별 및 제거
- **F606 (텍스트 데이터 증강)**: 전처리 및 부적절한 댓글 필터링을 통과한 데이터를 대상으로 GMS LLM API를 호출하여 기존 댓글의 의미와 감정을 유지하면서 자연스럽게 확장
- **F607 (데이터 통합 관리)**: 원본·정제·증강 데이터를 하나의 파이프라인으로 연결하고, Django 모델을 활용해 DB에 저장하며 단계별 분석 결과를 웹 화면에 통합 출력
- **F610 (댓글 요약 생성)**: 수집된 전체 원본 댓글을 기반으로 GMS LLM API를 활용하여 주요 투자 심리와 커뮤니티 반응을 객관적으로 요약

**1. 정규 표현식 및 LLM 기반 댓글 전처리 (F605)**

수집된 원본 댓글을 대상으로 정규 표현식을 활용한 데이터 정제 과정을 구현했습니다. 결측치와 빈 문자열을 제거하고, 댓글 길이를 5자 이상 76자 이하로 제한했습니다. 또한 반복적인 초성 및 불필요한 특수문자와 공백을 정리하여 분석에 적합한 텍스트 데이터로 가공했습니다.

기본 전처리 이후에는 GMS LLM API를 활용해 욕설, 혐오, 심한 비방, 선정성 및 과도한 인신공격 등이 포함된 부적절한 댓글을 판별하고 제거하도록 구현했습니다. 이 과정에서 정상적인 부정적 투자 전망이나 비판은 유지하도록 프롬프트를 구성했습니다.

**2. GMS LLM 기반 텍스트 증강 및 데이터 통합 (F606, F607, F610)**

전처리와 부적절 댓글 필터링을 통과한 댓글을 대상으로 GMS LLM API를 활용한 텍스트 증강 기능을 구현했습니다. 원본 댓글의 의미와 감정을 유지하면서 문장을 자연스럽게 확장하도록 프롬프트를 설계했으며, 확인되지 않은 사실이나 수치를 추가하거나 불필요한 투자 조언을 생성하지 않도록 제한했습니다.

또한 `services.py`에서 기본 전처리, LLM 기반 필터링, 텍스트 증강 및 댓글 요약 기능을 하나의 파이프라인으로 연결했습니다. 처리 결과인 원본·정제·증강 데이터를 Django 모델과 연동하여 DB에 저장하고, 분석 결과 페이지에서 각 단계별 데이터를 비교할 수 있도록 구현했습니다.

추가로 수집된 전체 원본 댓글을 기반으로 긍정적·부정적 반응을 균형 있게 반영하는 AI 요약 기능을 구현하여 사용자가 커뮤니티의 주요 투자 심리를 한눈에 파악할 수 있도록 했습니다.

※ 현재 `iqr_threshold` 필드에는 통계적 IQR 계산값이 아닌, 명세서의 댓글 길이 필터 기준인 하한 5자와 상한 76자를 저장합니다.

## 📌 회고 및 소감 (팀원 A)

**소준호**

- **소감 및 정리**
  - 정적 웹 스크래핑을 넘어 **Selenium**을 활용해 동적 웹 페이지(토스증권)의 검색 모달을 제어하고 실시간 데이터를 수집하는 웹 자동화 과정을 직접 구현해 볼 수 있었습니다. 사용자의 빈 값 입력 검증(`F601`)과 검색 결과가 없을 때의 예외 상황 처리(`F611`)를 구현하는 과정에 흥미를 느낄 수 있었습니다. 하지만 구현 과정에서 동적 웹 페이지 특성상 네트워크 속도나 토스증권 UI 변경에 따라 셀렉터가 간헐적으로 지연되거나 대기 시간이 길어지는 이슈가 있었고, 추후 해당 문제를 해결하기 위한 다양한 방안들을 탐색할 것입니다.

**김유민**

- **소감 및 정리**
  - 이번 프로젝트를 통해 단순히 데이터를 수집하는 것뿐만 아니라, 수집한 비정형 텍스트 데이터를 분석에 적합한 형태로 가공하고 활용하는 전체 과정을 경험할 수 있었습니다. 정규 표현식을 활용한 기본적인 전처리부터 GMS LLM API를 통한 부적절 댓글 판별과 텍스트 증강까지의 파이프라인을 직접 구현하면서 데이터의 품질이 이후 분석 결과에 큰 영향을 미친다는 점을 배울 수 있었고, Django 서비스와 데이터베이스를 통해 결과를 통합하며 기능 간 데이터 전달과 구조 설계의 중요성을 체감했습니다. 또한 LLM이 원본의 의미를 유지하면서 텍스트를 확장하도록 프롬프트를 설계하는 과정에서 생성형 AI를 실제 서비스에 적용할 때 고려해야 할 점을 배울 수 있었습니다.
  - 구현 과정에서 모듈 간 함수의 반환 자료형이 맞지 않아 파이프라인 연결에 문제가 발생하거나, DB migrations 및 화면 출력 과정에서 오류가 발생하기도 했습니다. 이러한 문제를 하나씩 확인하고 해결하면서 개별 기능의 구현뿐만 아니라 전체 시스템의 흐름을 이해하고 디버깅하는 역량을 기를 수 있었습니다.
